# 모두의 일정

사내 일정과 차량·공용장비를 함께 관리하는 실행 가능한 초기 버전입니다. Node.js 24 이상이 필요하며 외부 패키지 설치는 필요하지 않습니다.

## 실행

```powershell
node server.mjs
```

서버 PC에서 http://127.0.0.1:3000 에 접속하면 로그인 없이 로컬 관리자 권한으로 일정표를 사용할 수 있습니다. 관리자 화면에서 직원과 차량·장비를 추가합니다.

로그인을 다시 활성화하려면 실행 전 `$env:AUTH_REQUIRED='1'`로 설정합니다. 기존 관리자 계정이 없다면 인증 활성화 전에 관리자 화면에서 이메일·비밀번호를 지정한 관리자 계정을 추가하세요. 자동 생성된 로컬 관리자 계정은 로그인 비밀번호를 제공하지 않습니다.

## 검증

```powershell
node --test test.mjs
```

## 구현 범위

- 이메일·비밀번호 로그인, 관리자 계정 관리와 비밀번호 변경, 비활성 세션 차단
- PC·모바일 월간 일정표, 주간·일간 목록과 담당자·분류·자원 필터
- 공동 일정 편집, 버전 검사, 예약 충돌 경고와 확인 후 저장
- 매주·매월 날짜·매월 주차/요일 반복, 회차별 또는 전체 수정·삭제
- 최근 변경 30건, 전체 변경 알림, 담당·동행자 시작 30분 전 내부 알림
- SQLite 영속 저장, 서버측 권한 검증, 로그인 실패 횟수 제한

## 현재 제한과 다음 작업

- 반복 기간은 최대 2년입니다. 존재하지 않는 월 날짜·주차는 건너뜁니다.
- 전체 시리즈 수정은 개별 수정 회차를 포함하여 내용·참여자·자원을 덮어씁니다. 시작·종료 시간은 회차별 수정 또는 재등록으로 변경합니다.
- 주간·일간은 목록형입니다. 달력 드래그 이동, 종일 일정, 브라우저 푸시는 포함하지 않았습니다.
- 알림은 서버 실행 중 생성되며 사용자가 새로고침하거나 알림 창을 열 때 확인합니다. 실시간 푸시·외부 메시지 작업 대기열·카카오톡 발송은 후속 구현입니다.
- 비밀번호 초기화는 관리자 화면에서 새 비밀번호를 지정하는 방식입니다. 일회성 초기화 링크와 첫 로그인 강제 변경은 후속 작업입니다.
- 자원 메모, 변경 내역 더 보기, 알림 보관 정책과 자동 백업·복구 도구는 후속 작업입니다.
- 현재는 신규 선택 목록에서 비활성 직원·자원을 제외하며, 기존 일정에서 선택된 항목은 유지합니다.

## 배포와 데이터

기본값은 서버 PC에서만 접속하는 `127.0.0.1:3000`입니다. 운영 배포 전에 접속망·HTTPS·백업 정책을 확정해야 합니다. 임의로 외부 공개하지 마세요.

환경 변수: `HOST`, `PORT`, `DB_PATH`, `COOKIE_SECURE`를 지원합니다. HTTPS 역방향 프록시를 사용하는 운영 환경에서는 `COOKIE_SECURE=1`로 설정합니다. 요청 Host/Origin이 외부 접속 주소와 일치하도록 프록시를 구성합니다.

데이터는 `data/schedule.sqlite` 및 SQLite WAL 파일에 저장됩니다. 수동 백업은 서버를 정상 종료한 뒤 `data` 폴더 전체를 복사하는 방법을 사용합니다. 복원은 서버를 멈춘 상태에서 백업 폴더로 교체한 뒤 실행합니다. 운영 전 별도 복사본에서 실제 복구를 검증하세요.

운영 환경과 사용자 수가 아직 확정되지 않았으므로 성능 검증·HTTPS 배포·복구 시험을 완료한 운영 배포본은 아닙니다.
